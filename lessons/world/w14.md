## 任务：判断一条测量是否值得行动

探测器按四条预设记录工作。每条含测量值 value、数据年龄 age、单位 unit 与顺序 time。规则先检查单位是否为 model；再在启用新鲜度检查时要求 age≤maxAge。只有可用数据才比较阈值 7：大于 7 发出 MOVE，否则 WAIT；不可用则 HOLD。

这是任务定义的保持策略，不是所有设备都应当如此。MOVE、WAIT、HOLD 是网页中的符号，没有机械执行器。maxAge 与阈值也是归一化教学参数，不是医疗、航空或真实星际探测任务参数。

第三条记录 age=8、value=9。如果最大年龄 3 且启用检查，它已经过时，应 HOLD；关闭检查则可能 MOVE。即使 9 在合法数值范围内，仍不代表它适合当前决策。第四条可改成未知单位，应该拒绝使用，不能默认把它当成常见单位。

## 为什么“先验证”会贯穿所有案例

起搏器命令要确认与验证；竞态要绑定配置版本；千年虫要保留世纪；阿丽亚娜要尊重类型范围与有效状态；火星轨道器要核对单位；长期计时要分析误差；调度要保证关键工作预算；深空命令要区分重试；位错误要在保证范围内纠正；生命探测要区分信号与结论。

共同点不是“多写几个 if”，而是知道程序里的一个值来自哪里、对应什么时间、携带什么单位、在哪些条件下可信、出错后由谁决定下一步。把这些问题写进数据结构、接口、测试与文档，代码才能承担可解释的职责。

观察这点尤其重要：如果你把年龄上限随便放宽，测试也许全部“通过”，但你只是改变了需求。工程改进应解释为什么新边界符合物理过程与任务，而不是为了让报警消失。

## 实验记录应该怎样写

| 项目 | 一份能被复查的记录 |
| --- | --- |
| 目标 | 检查过时测量是否能触发 MOVE |
| 前提 | 固定四条记录，maxAge=3，单位均为 model |
| 预测 | 检查开启时第三条 HOLD，关闭时 MOVE |
| 操作 | 只修改 freshness，重新计算并走到第三帧 |
| 实测 | 记录 action、age、usable 与摘要计数 |
| 解释 | usable 中年龄条件因开关被跳过 |
| 边界 | 不覆盖真实导航、传感器损坏或执行机构失效 |

写“演示正常”不够，因为别人不知道你测试了什么。写“这个算法绝对安全”也过头，因为证据只覆盖明确的场景。可复现的输入、明确的预期、可见的中间状态与适度的结论，比一句很有把握的评价更有价值。

## 进一步修改：让证据超出默认路径

在正文编辑器里复制并修改 records，可测试一个恰好 age=3 的边界、重复时间戳、缺失单位、负年龄、NaN 或非常大的值。当前固定记录模型只验证年龄上限与单位，**没有实现任意外部遥测的完整解析器**；新增外部输入时，应先写数据形状和数值校验，再讨论动作。

还可以设计命令号，让 MOVE 结果经深空链路返回；加入掉电后的去重恢复；对档案数据加纠错；给任务设置预算。每加一层都先声明模型与接口，避免一口气堆出没有人能解释的复杂动画。高亮与状态记录应继续来自实际计算，不能换成手写的“正确故事”。

## 零基础继续学什么

想读懂这些程序，回到 JavaSE 学变量、条件、循环、函数、数组与异常；再用 Java 重写其中一个模型，比较语言规则。想理解通信，学网络、序列化与消息重试；想处理实验数据，学统计、线性代数与数值方法；想做实时系统，学操作系统、控制理论与硬件接口。

医学、航空、天文学还各有专业知识与实际工作要求。会写代码是参与的工具，不会自动替代领域专家。与此同时，你不必等到成为所有领域专家才开始贡献：数据平台、可视化、自动化测试、开放数据整理和可复现研究都是真实工作。

## 编程与生活的距离究竟有多近

看病时的身份匹配、飞机上的时间同步、相机去噪、天气预测、导航地图、粮食供应链、灾害预警都依赖计算。软件并不独自创造医学、飞行或科学发现，却把观测、知识和决策连接到可重复执行的过程。过程一旦规模化，正确的规则会帮助很多人，隐蔽的假设也会影响很多人。

因此学习编程不仅为了“让它跑起来”，也为了理解系统怎样影响别人。尊重未知、记录证据、维护可解释的边界，并不削弱好奇心，反而让我们有能力把好奇心变成可靠的探索。

## 最后一个自测：你现在能回答了吗

“一个回车”背后有授权、通信、验证与固件状态机；千年虫来自信息表示与长期假设；航天偏差来自软件错误穿过接口和控制链；寻找生命依赖算法与独立证据；文明代码的保存则需要介质、规格与解释者。若你能给每句话补上一条实验观察和一个边界条件，就已经从听故事走向理解原理。
